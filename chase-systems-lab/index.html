Systems Lab

Engineering notes on the technical architecture behind this site — structured data, automated maintenance, and how pages actually get discovered. Written for anyone curious about the mechanics rather than the pitch; see PBSA Overview for the conceptual version.

Log

Structured data integrity pass

2026-07

Every JSON-LD block on the site was audited for validity. Thirteen pages had malformed @graph entries — mostly a missing closing brace on an ImageObject or Question node before the next sibling started, which silently breaks the entire script tag as far as a JSON parser (and Google's Rich Results parser) is concerned. All blocks now parse cleanly. Lesson: structured data that "looks right" in a code editor can still be invalid JSON — it needs to be parsed, not just eyeballed.

Maintenance automation rework

2026-07

The monthly refresh job that generates /maintenance/YYYY-MM/ pages was auditing clean but producing two problems: the archive index's list-update step appended new entries after the closing </html> tag instead of inside the list, and the dated pages themselves were marked indexable despite carrying no unique content beyond a rotating stock image. Fixed the archive template so entries are inserted correctly, and switched the dated pages to noindex,follow — they still pass link equity to the pillar pages they reference, but they no longer compete as near-duplicate thin pages in the index. Automation should reinforce the pages with real content, not multiply pages that don't have any.

Discovery pipeline: IndexNow + sitemap ping

2026-07

Added an IndexNow key file and a workflow step that submits changed URLs to the IndexNow API on every deploy, plus a Bing sitemap ping. This gets new and updated pages into Bing/Yandex/Seznam's crawl queues within minutes instead of waiting for a scheduled crawl. Google deprecated its sitemap ping endpoint in 2023 and doesn't participate in IndexNow, so Google discovery still runs through robots.txt → sitemap.xml → Search Console, same as before.

Current architecture, in short

  • Entity layer: one canonical Person node (#chase-arenella) referenced by @id across every page instead of restated inline, so updates only need to happen in one conceptual place.
  • Pillar + hub structure: a small number of deep pages (Leadership, Gaming, Work, Projects) rather than many shallow ones, cross-linked through BreadcrumbList and internal links.
  • Media coverage: every image under /assets/images/ is cataloged with alt text, caption, and ImageObject schema on Media and Creative — no orphaned images.
  • Discovery: sitemap.xml + image-sitemap.xml, referenced from robots.txt, plus the IndexNow/Bing ping above.
